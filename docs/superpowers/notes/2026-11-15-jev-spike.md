# Jev spike: results (2026-11-15)

**Setup:**
- Script: `visual-qa/spike/jev-spike.ts`. Raw responses are in `visual-qa/test/fixtures/jev/*.json`, with the summary in `_summary.json`.
- 12 single decisions: 11 on local fixture pages and 1 on `en.wikipedia.org/wiki/Espresso`.
- Model resolved as `jev-1.13.x` via `jev-latest`.
- The key was read from the project's `.visual-qa/.env` and never printed.
- The script was run twice: run 1 used the original operation wording, run 2 the revised wording.

## Measurements

| | Run 1 | Run 2 |
|---|---|---|
| Latency per decision | 167–336 ms (median ≈ 220 ms) | 134–327 ms (median ≈ 190 ms) |
| Correct picks | 9 / 12 | 9 / 12 |
| Wrong actions that would have executed at threshold 0.7 | 0 | 0 |

**Request size:**
- Small pages: ~600–750 input tokens.
- `busy.html` (300 links, capped at 254 targets): ~12.4k input tokens.
- Wikipedia (890–1,099 controls, capped at 254): ~10.4k input tokens.
- Output tokens grow with the number of target options, up to ~2.3k. Output is free.

**Cost:** at $0.042 per million input tokens, a busy-page decision costs about $0.0005, and a small page about $0.00003.

**Usage fields:** the JS SDK result has `usage.input_tokens` / `usage.output_tokens`, which can be null. These are snake_case, as in the REST API. The client normalises both spellings.

## Findings and changes

1. **Click vs type on text fields** (run 1).
   - "Fill the name field" got `type` 0.54 vs `click` 0.46, so confidence was 0.47. "Fill Straße" got `click` 0.53 vs `type` 0.47.
   - In both cases the target was right at 1.00, and p(click) + p(type) = 1.00.
   - **Change:** the operation descriptions now say click is "not for filling in a text field" and type is "fill in a text field with a value". In run 2, the same steps got `type` at 0.98 and 0.97.
   - **Safety net (Task 6 ruling):** for a text-like target, treat click/type as one intent, using p(click) + p(type) as the confidence and executing `type`.
2. **`press_enter` without a target.**
   - "Search for espresso" after typing got `press_enter` at 0.93 (run 1) and 0.99 (run 2), but target `none`, with target confidence of 0.20 and 0.06.
   - **Change (Task 6/7 ruling):** `press_enter` doesn't need a target. The runner presses Enter on the target if one is given, otherwise on the last field typed into in this step, otherwise on the focused element.
3. **Iframe content is invisible to Jev** (main-frame snapshot). It answered `wait` at 0.67 and 0.58. Both are below 0.7, so the result is a hand-back with `low_confidence`, as the spec intends: Claude handles iframes. No change needed.
4. **Busy real page (Wikipedia).** Run 1 got the correct click at 0.84. Run 2 got `done` at 0.45, which is below the threshold and so a safe hand-back. Jev is less stable on very large pages, and the threshold catches it.
5. **Threshold 0.7 stays.** Every correct pick in run 2 scored ≥ 0.92. Every wrong or unsure pick scored ≤ 0.67.
6. **Target cap of 254 and a 3,000-char text excerpt stay.** The 300-control page still answered in 327 ms, with the right target out of view (Item 250, at 0.99).

`DEFAULTS` are unchanged.
